## 2. What worked

- The label gate was enough authorization for a whole cycle: one owner label
  (08:47) covered six audited sends; no per-message chat confirmation.
- Review found defects that green gates passed: cross-review caught the
  Codex command in `agents/coordinator/AGENTS.md:12` (#32 review, finding 1);
  the #112 author's own review round (8/10) caught a failing acer rollback
  command before the cross-review.
- Completion versus verification held: the checkpoints report a worker's
  `done` separately from verification (09:14: "engineering acceptance and
  merge are still open"), and nothing was merged (09:32 checkpoint: "none yet
  mergeable").
- Checkpoint comments on the issue made the cycle reconstructible from GitHub
  alone; this report was written from them.

## 3. What did not work, or needed a workaround

- **`herdr:await` ends at the first turn end.** It waits for a turn to start
  and then for idle/done/blocked, at most `timeout_s` ≤ 1800
  (`task-modules/herdr.nix:190-214`). A worker that waits on background jobs
  goes idle between turns, so await returned long before the work was done;
  the coordinator followed up with `herdr agent wait` instead (coordinator
  observation, no audit record).
- **One heavy-work lock on acer serialises both workers**: parallel coding,
  sequential verification (09:14 checkpoint). It cost little today: both
  #112 gate runs got the lock at once (queued and started 08:56:56 and
  09:17:00).
- **Same-account reviews**: GitHub does not accept an APPROVE from the PR's own
  account, so all three reviews are comment reviews with the verdict in the
  body (09:31 checkpoint; review URLs above show state `COMMENTED`).
- **Codex adapter load is unproven**: neither the shipped `AGENTS.md` (#32)
  nor #112's generated `coordinator.toml` has been loaded by Codex in a real
  session; proof is the lenovo validation step in #112's
  `docs/rollout-coordinator.md` (09:25 checkpoint).
- **The first Codex adapter broke in fish**: `$'\n\n'` is a fish parse error,
  and `$(cat agents/…)` reads empty outside the checkout, dropping the role
  text (#32 review, finding 1, reproduced on acer).
- **`herdr:inspect` showed only the visible screen**, because the task's
  default is `source = "visible"` (`task-modules/herdr.nix:57`); it already
  accepts `recent` and `recent-unwrapped` (`:67`).

## 4. Tooling versus procedure

Needs a (small) change to existing tasks:
- `herdr:message` writes `task_ref` into the audit attempt record, so recovery
  needs only `audit.jsonl` (#32 review, finding 3).
- `coord:brief` reports `audit_corrupt` instead of an empty handoff list (#32
  review, finding 4).
- `herdr:inspect` defaults to `source = "recent"` (one word).
- One Codex adapter file, no shell-out (09:31 decision; #32 fix, audit
  `0e68e44e1c8e`).

Procedure only, no tooling:
- Completion is `work:status` against GitHub, not `herdr:await`; use await to
  confirm a turn started, `herdr agent wait` or a later tick for the rest.
- Heavy gates queue on the lock; the capacity rule in `docs/process.md`
  (#32) is the whole scheduler.
- Comment reviews carry the verdict in the body; a formal APPROVE needs a
  second GitHub identity, which is an owner decision, not tooling.
- Codex load is proven by the lenovo validation conversation, once.

Not needed by this pilot: `coord:loop`, a scheduler, cron re-arm, `coord:spawn`,
model tiers. Six sends in about 45 minutes ran as hand-driven ticks.
